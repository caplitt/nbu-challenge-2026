# Як оновлювати проєкт до дедлайну і фіналу

Усе перебудовується однією командою: `python build.py --fetch` (дані → графіки → прогноз → документи → презентація → PDF → тести).

## Календар

| Дата | Подія | Що робити |
|---|---|---|
| 9–10 жовтня | Держстат: ІСЦ за вересень | `python build.py --fetch`; перевірити `results/tables/cpi_nowcast.csv` (вересень стане фактом) і слайд «Короткостроковий прогноз» |
| до 20 жовтня | Дата відсічення даних | зафіксувати; вказати на слайді «Головне» (`deck/content.py`, поле `data_cutoff`) |
| будь-коли | Уточнення ВВП II кв. / нові оцінки | `update_data.py` → `GDP_UPDATES`; `config.py` → `GDP_NOWCAST` |
| **28 жовтня** | **Подача робіт** | фінальний `python build.py`, подати `presentation/NBU_University_Challenge_2026.pdf` (і `.pptx`) |
| 29 жовтня | Рішення НБУ і новий макропрогноз | порівняти з нашою рекомендацією; підготувати пояснення відмінностей |
| 5 листопада | Інфляційний звіт НБУ (жовтень) | завантажити нові `Tables_Charts_*.xlsx` і `Macroeconomic_Forecast_table_*.xlsx` у `data/raw/nbu/`, оновити шляхи в `qpm/nbu_files.py` |
| 9 листопада | Результати відбору | — |
| ≈10 листопада | ІСЦ за жовтень | `python build.py --fetch` |
| 26 листопада | Фінал | репетиція з `docs/qa_prep.md`; рішення НБУ 29.10 — у слайд «Головне» |

## Що де міняти

| Хочемо змінити | Файл |
|---|---|
| Рекомендоване рішення (наприклад, утримати 16%) | `config.py` → `RECOMMENDATION["option"]` (і тексти в `deck/content.py`) |
| Судження, сценарії, курсову траєкторію | `config.py` |
| Короткостроковий прогноз ІСЦ | `config.py` → `CPI_NOWCAST` (поправка `adjustment`) |
| Параметри моделі (β, ціль тощо) | `model/params.yaml` |
| Рівняння | `model/model.model` |
| Тексти слайдів | `deck/content.py` |
| Назва команди, університет | `deck/content.py` → `TEAM` |
| Вигляд слайдів | `deck/build_deck.js` |

## Перевірка перед подачею

1. `python -m pytest -q` — усі тести зелені (зокрема: цифри на слайді «Головне» = результати моделі).
2. Переглянути PDF: жодного «[назва]» у тексті, дати й цифри актуальні.
3. Кожен у команді може пояснити будь-який слайд (див. `docs/qa_prep.md`).
